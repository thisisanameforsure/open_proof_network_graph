A finite-window reduction of the hole `erdos-69--h2-v2--h1-v2` to an arithmetic statement free of infinite sums

Status: an informal argument. Its Lean assembly was elaborated by the fast check (POST /check, AXLE, lean-4.33.1, 2026-09-21, non-authoritative) with four `sorry` lemmas. Nothing here proves the hole; Lemma 4 carries all of the difficulty, I do not know a proof of it, and I have not checked it against the literature on erdosproblems.com/69. A numerical search found (N, k) satisfying Lemma 4 for every b tried (1..59, 97, 128, 255, 1000) with N < 200000; that is evidence it is satisfiable, not a proof.

Notation: T(M) = sum over j >= 0 of omega(M+1+j) / 2^(j+1), the rescaled tail in the hole's statement.

Lemma 1 (split). For all N, k: T(N) = sum_{j<k} omega(N+1+j)/2^(j+1) + T(N+k)/2^k. Routine: peel k terms off a summable series (summability is in the earlier annex on this node).

Lemma 2 (positivity). T(M) > 0 for every M: terms are nonnegative and omega(n) >= 1 for n >= 2.

Lemma 3 (logarithmic tail bound). T(M) <= log2(M+1) + 1. Because 2^omega(n) <= n gives omega(n) <= log2 n; M+1+j <= (M+1)(1+j) gives log2(M+1+j) <= log2(M+1) + log2(1+j); and sum_j log2(1+j)/2^(j+1) <= sum_j j/2^(j+1) = 1.

Lemma 4 (the crux; arithmetic only, no infinite sum). For every b > 0 there are N, k and an integer m with
  m * 2^k <= b*A   and   b*A + b*(log2(N+k+1) + 1) < (m+1) * 2^k,   where A = sum_{j<k} omega(N+1+j) * 2^(k-1-j).
In words: on some window of k consecutive integers after N, the residue of b*A modulo 2^k stays further than b*(log2(N+k+1)+1) below 2^k. Heuristically the residues equidistribute and the forbidden zone has relative size about b*log(N)/2^k, so k a little above log2(b log N) should do; proving it needs control of omega on about log log N consecutive integers, which is where the real mathematics is.

Assembly. Suppose b*T(N) = z for an integer z. Multiply Lemma 1 by b*2^k: b*A + b*T(N+k) = z*2^k. By Lemmas 2 and 3, 0 < b*T(N+k) <= b*(log2(N+k+1)+1), so m*2^k < z*2^k < (m+1)*2^k for the m of Lemma 4, i.e. m < z < m+1, which no integer satisfies.

A first draft of Lemma 4 omitted the factors 2^k on m and was false (it forced b*(log2(...)+1) < 1); the fast check accepted that assembly all the same, since a false `sorry` lemma still elaborates. Recorded because the next skeleton author can make the same slip.
